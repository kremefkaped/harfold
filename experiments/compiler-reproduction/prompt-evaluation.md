# Which evidence should change the next instruction?

The compiler case exposed a misleading shortcut. A nonzero exit can be a missing compiler or a newly broken comment. A zero exit can also accompany zero executed tests. The current repair brief therefore uses the completed observations, their original source coordinates and the selected file's digest. It asks for a fresh reproduction when the target survives. When the signal is lost it asks the recipient to return to a previously confirmed input.

In a separate controlled test, a Node runner emitted native TAP and JUnit records from the same executions. A naive paired rule accepted all four contrasts when it used only a successful control exit, a failing exit and a string anywhere in the bad run's log. Only one of those contrasts was a true named-test reproduction. Three traps printed the expected phrase and then raised a different error, skipped the named control test, or omitted it entirely.

We also tested the previous intake prompt and a proposed addition. Two fresh agent sessions received the same task, one example pair, and the same required application assertion. Each wrote a Python program to classify recorded runs. One prompt added these instructions:

> Bind each verdict to exactly one matching native test-case record per run. Check the failing assertion’s own message, error class and application frame. Treat copied log text, a skipped or absent case, and an assertion at another site as insufficient.

The nine pairs were frozen before dispatch. The positive example was visible to both participants. The remaining eight pairs included a wrong assertion site, duplicate case names, a failed control process, a skipped bad case and a real failure with unrelated log noise. **Both generated verifiers classified all nine pairs as expected.** This small comparison gave no evidence that adding the instruction improved accuracy over the previous prompt. It measured interpretation of test records; a runner-reported pass alone cannot prove a user-visible outcome.

# Does the repair handoff change the outcome?

On 10 November 2026 we gave two fresh coding-agent sessions the same broken component, symptom report, working and broken recordings, ordinary Markdown comparison and local CLI. One session also received a JSON acceptance check generated by Harfold v0.1.0 and its repair prompt. Both had to restore the displayed product and preserve normal compression behavior. Neither was given the upstream fix, access to the other seat or the evaluator.

The organizer kit contains two separate participant archives, the frozen checks and the two candidate repairs. Give each participant only one inner archive. Reproducing the historical case requires Python, Node and local Chrome. [Download the organizer kit](https://kremefkaped.github.io/harfold/experiments/acceptance/handoff-trial.zip)

| Independent check | Ordinary report | Report + rule and prompt |
| --- | --- | --- |
| Nine held-back compression and streaming cases | 9/9 | 9/9 |
| Fresh Chrome session after repair | Mug × 2 | Mug × 2 |
| Fresh recording checked by the evaluator | Valid JSON | Valid JSON |
| Unauthorized input or runner changes | 0 | 0 |

Both repairs preserved pre-encoded data and ordinary gzip compression. The ordinary-report recipient additionally compared the final transfer size. The rule-and-prompt recipient ran the supplied JSON rule before and after the repair. Each independently added three tests. Only the held-back checks and a fresh browser run determined success.

The same evaluator gave the original 0.21.0 component 6/9 and the published 0.22.0 fix 9/9. Its checks covered pre-encoded gzip, pre-encoded chunks, pre-encoded deflate, ordinary large and small bodies, identity-only clients, unencoded streams, a pre-encoded response without Accept-Encoding, and empty responses. Both participants had the affected component and a working reproduction command from the start. This removed the cost of preparing a reproducer. With one agent per condition, a ceiling result and no reliable human time measurements, the trial supports sufficiency of both handoffs for this task. It gives no basis for a speedup or adoption claim. [Underlying incident and reproduction](gzip-case.md)

## What maintainers requested

We checked a separate convenience sample of twelve public issues and their 46 comments. At 03:13:48 UTC on 10 November 2026, we selected the four newest non-PR reports still bearing Vite’s `needs reproduction`, Next.js’s `please add a complete reproduction`, or Astro’s `triage: needs reproduction` label, per repository and across all states. All twelve happened to be closed. Bot reminders were distinguished from individual maintainers’ replies.

A reproduction-label sample favors reports already missing a runnable example. It cannot estimate demand among performance engineers or the prevalence of network regressions.

## A prompt for the first handoff

Before asking a reporter to collect more evidence, try the following prompt. This is a proposed intake prompt. The agent comparison above tested Harfold v0.1.0’s already-generated repair prompt.

> Write down the user action, the expected result and the observed failure. Identify the shortest existing command or test that distinguishes them. If you can run it, record the revision, command, exit status and matching failure signal. Treat setup errors and zero executed tests as separate outcomes. If a supplied example never exercises the affected behavior, name the missing action or file. Ask for the smallest additional artifact that would change the diagnosis. Request a recording when a specific HTTP observation matters. When a working control is available, run the same check against it. Label every result as observed, reported by someone else, or still unverified.

An Astro triage report outside the fixed sample describes running the same project against two dependency versions. That is a concrete existing implementation of version comparison after submission. A possible next field experiment is whether reporters can prepare an equally usable reproducer earlier with less effort.
